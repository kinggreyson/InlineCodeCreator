# Communication & Maintainer Norms

## Who maintains this project

Inline Code Creator is currently maintained by one person, Greyson King (@kinggreyson). I'm a full-time student, so this project currently runs on student hours.

## Where discussion happens

All project discussion happens here in GitHub Issues on this repo. That keeps every question, idea, and decision in one searchable place that anyone can read later. Please don't send contributions or questions by DM or email, because they're easy to lose and nobody else can learn from them.

- **Bug or something not working:** open an issue with the bug form.
- **Idea or feature request:** open an issue with the feature form.
- **Question about the code or how to get started:** open an issue with the question form.
- **Pull requests:** please link the issue they address. For anything bigger than a small fix, open an issue first so we can agree on the approach before you invest time.

## Response expectations

- **First response on a new issue or pull request:** within 4 days.
- **Follow-up replies after that:** within a week.
**Warning** During time off for Holiday breaks this response time may be longer.

If you haven't heard back after the stated time, leave a comment on the issue.

## How I keep that promise

Every issue form automatically applies a `needs triage` label to new issues. I remove the label only after I've read the issue and replied. I'll open the filter every Monday and Friday `is:issue is:open label:"needs triage"` and work through it until it's empty. Anything still carrying the label is something I haven't answered yet, so nothing can quietly slip through.

## How decisions get made

As the sole maintainer, I make the final call, but I make it in the open:

1. **Where:** the decision happens in the issue thread, not in private.
2. **How:** I explain my reasoning in a comment, weighing the proposal against the original project's goals (a notes-first editor with runnable, clearly formatted code) and the maintenance cost.
3. **Outcome:** I will label the issue `accepted`, `declined`, or `needs discussion` and either close it with an explanation or leave it open for work.

If you disagree with a decision, reply in the thread with your reasoning. I'm happy reflect and see your reasoning
